# `docs/dev/` — maintainer-facing technical notes

These files are not part of the rendered MkDocs site — they live here for the next dev
who needs to understand a workaround, a design decision, or a known issue in the
codebase. Each one is self-contained and references the relevant source paths.

| File                                                       | What it covers                                                                                                                                                                                                                                                                                                                          |
| ---------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [hydromt_sfincs_issues.md](hydromt_sfincs_issues.md)       | 14 upstream bugs in `hydromt-sfincs` and `hydromt` that we patch around in `src/coastal_calibration/sfincs/_hydromt_compat.py`. The dependency is pinned in `pyproject.toml` to commit `41aac0a` so the patches stay aligned with the upstream API they were written against. Re-evaluate when the upstream maintainers ship the fixes. |
| [stofs_tpxo_improvements.md](stofs_tpxo_improvements.md)   | Four-phase plan for replacing the current STOFS / TPXO boundary pipeline. Phase 1 (STOFS-aware TPXO fallback), Phase 2 (multi-cycle STOFS stitching), Phase 3 (regional STOFS subsetting), and Phase 4 (pure-Python TPXO module) are mirrored in the top-level README roadmap; this file is the design rationale.                       |
| [sfincs_compilation.md](sfincs_compilation.md)             | Manual SFINCS build instructions for non-pixi environments (Ubuntu apt, macOS Homebrew). The pixi-managed build is the supported path; this is a fallback for niche setups.                                                                                                                                                             |
| [schism_sink_source_issue.md](schism_sink_source_issue.md) | Spurious source/sink point duplication in the pre-built SCHISM meshes. Not fixable from this package (mesh generation is upstream); flagged here so the next person to build a SCHISM mesh knows to use the SFINCS-side `_inflow_intersection_point` strategy.                                                                          |
