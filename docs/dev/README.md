# `docs/dev/` — maintainer-facing technical notes

These files explain a workaround, a design decision, or a known issue in the codebase,
for the next dev who has to touch it. Each one is self-contained and references the
relevant source paths.

They **are** published on the MkDocs site, under "Developer Notes" — only this index
page is excluded (see `exclude_docs` in `mkdocs.yml`). Write them for an outside reader.

| File                                                         | What it covers                                                                                                                                                                                                                                                                                                                                                                                       |
| ------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [hydromt_sfincs_issues.md](hydromt_sfincs_issues.md)         | 14 upstream bugs in `hydromt-sfincs` and `hydromt` that we patch around in `src/coastal_calibration/sfincs/_hydromt_compat.py`, plus one local compatibility shim for ngen forecast forcing. The dependency is pinned in `pyproject.toml` to commit `41aac0a` so the patches stay aligned with the upstream API they were written against. Re-evaluate when the upstream maintainers ship the fixes. |
| [stofs_tpxo_improvements.md](stofs_tpxo_improvements.md)     | Status of the STOFS / tidal boundary pipeline. Pure-Python tidal prediction is delivered (pyTMD); bandwidth is handled by time subsetting. What remains is multi-cycle stitching, which is blocked on cycle-to-cycle continuity — where consecutive STOFS cycles differ at the same valid time, the step enters both coastal models as a small wave.                                                 |
| [schism_source_sink_design.md](schism_source_sink_design.md) | Why a SCHISM discharge crosswalk contains several source and sink points along one river, why that is correct for contour-following NWMv3 meshes, and what to do differently when authoring a new mesh. Also records the one genuine gap: this package cannot produce a SFINCS sink, which the Great Lakes will need.                                                                                |
| [sfincs_compilation.md](sfincs_compilation.md)               | Manual SFINCS build instructions for non-pixi environments (Ubuntu apt, macOS Homebrew). The pixi-managed build is the supported path; this is a fallback for niche setups.                                                                                                                                                                                                                          |
